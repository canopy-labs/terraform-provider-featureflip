# Featureflip Provider

The Featureflip provider manages [Featureflip](https://featureflip.io) resources through the public Management API: projects, environments, feature flags (including variations and per-environment targeting), user segments, SDK keys, and outbound webhook subscriptions.

## Authentication

Create an API token in the Featureflip dashboard:

- **Service token (`ffs_…`) — recommended.** Organization Settings → Service Tokens. Scoped to one organization with a role (use Member or Admin; Viewer tokens cannot write, and webhooks require Admin) and an optional project allowlist.
- **Personal access token (`ffp_…`).** Acts as your user across your organizations.

Tokens cannot be created through the public API — only through the dashboard.

Set the token via the `FEATUREFLIP_TOKEN` environment variable rather than in configuration where possible.

## Example Usage

```terraform
terraform {
  required_providers {
    featureflip = {
      source  = "canopy-labs/featureflip"
      version = "~> 0.1"
    }
  }
}

provider "featureflip" {
  organization = "acme-corp"
  # token via FEATUREFLIP_TOKEN environment variable (recommended),
  # or: token = var.featureflip_token
}
```

## Upgrading to v0.4.0

v0.4.0 adds three lifecycle attributes: `owner_email` and `permanent` on `featureflip_feature_flag`,
and `default_flag_lifetime_days` on `featureflip_project`. All three are opt-in, so an existing
configuration plans with no changes after the upgrade:

- **Omitted means unmanaged.** Terraform leaves the value alone: an owner, permanent marker or
  default lifetime set in the dashboard is kept, and so is the owner the API assigns when a flag is
  created with a personal access token (the creating user). Flags created with a service token
  start unowned.
- **To clear a value, set it explicitly:** `owner_email = ""` leaves the flag unowned,
  `permanent = false` makes it temporary, and `default_flag_lifetime_days = 0` removes the project
  default. In state, an unowned flag reads as `""` and a project without a default as `0`.
- **Removing one of these attributes from config stops managing it**; it does not clear the value.
- **Archived flags are read-only**, apart from clearing the owner, the permanent marker or the
  expiry. A plan that would change anything else on a flag that stays archived fails at plan time;
  set `archived = false` in the same apply to restore it first. A value that isn't known until
  apply (one computed from another resource) can't be checked at plan time: the plan warns, and
  the apply fails if the value turns out to change the archived flag.
